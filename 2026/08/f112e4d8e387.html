动态规划

发表于2026-08-27|更新于2026-09-02|面试
|总字数:1.7k|阅读时长:6分钟|浏览量:

哎哟我去，什么叫复习算法第二天搞动态规划（

动态规划核心框架中，通常包含四个核心要素：

  • Base Case：最基础的情况（初始条件）。
  • 状态（State）：随着问题规模推进而变化的变量。
  • 选择（Choice）：导致状态发生变化的行为（通常伴随 min / max 来找最优解）。
  • dp 数组/函数的定义：如何用数学语言表达当前状态下的最优值。

整体的动态规划思路如下

明确「状态」-> 明确「选择」-> 定义 dp 数组/函数的含义。

看上去简单但是怎么做就难了。我的想法是想办法在脑海里面复现怎么一步步把问题缩小，在这个过程里面去寻找。

使用场景

问题具有最优子结构。要符合「最优子结构」，子问题间必须互相独立，互不影响。

示例

leetcode No.322
给你一个整数数组 coins，表示不同面额的硬币；以及一个整数amount，表示总金额。计算并返回可以凑成总金额所需的最少的硬币个数。如果没有任何一种硬币组合能组成总金额，返回 -1。你可以认为每种硬币的数量是无限的。

输入：coins = [1, 2, 5], amount = 11
输出：3
解释：11 = 5 + 5 + 1

输入：coins = [2], amount = 3
输出：-1

输入：coins = [1], amount = 0
输出：0

经典的硬币找零问题，按照思路来的话：

明确状态

随着我们取出不同面额的硬币，变量当前金额和当前硬币个数会变化。
不过当前硬币个数这个东西是我们的状态的返回值，也是我们最终要求解的目标。从子问题的角度来说这个就是子问题的最终答案，肯定不能把答案当成当前状态对吧。
所以这里的唯一状态是当前金额。
动态规划问题中状态并不是唯一的

明确选择

很显然，我们如果需要继续前进就要选择取出哪个面额的硬币。
比如说选择了1，问题就变成了已经有1枚硬币的情况下计算凑齐amount-1所需的硬币个数1+dp(amount-1)。选2和5同理.
他说要最少硬币个数，那就是min(1+dp(amount-1),1+dp(amount-2),1+dp(amount-5))，dp函数又会一直递归下去，直到碰到base case返回。
dp[amount] = min(1+dp(amount-1),1+dp(amount-2),1+dp(amount-5))就是传说中的状态转移方程

定义 dp 数组/函数的含义

知道了状态转移方程,dp[i]就是当前的状态，其中i表示当前金额.那么，dp[i]表示凑出金额为 i 时所需的最少硬币数。

至此整个思路就完成了

base case呢，怎么忘了他？

Base Case通常在以下两个时机被确定：

  • 刚确定 dp 数组定义后根据你对 dp[i] 的定义，直接寻找问题规模最小、不需要任何计算就能一眼看出答案的情况。
    例如既然定义了dp[i]是凑齐金额i的最少硬币数，那么最简单的规模显然是i = 0，凑0元需要0枚硬币，直接得到 dp[0] = 0。
  • 在写状态转移方程遇到边界时
    例如当面额大于剩余金额导致i - coin < 0时，转移会越界，因此需要定义负数金额对应的值为正无穷。

试着刷了打家劫舍的经典问题，结果最简单的没想出来（，主要还是状态和选择没有明确（其实是忽略了哥们是从头抢到尾的）。
打家劫舍1的状态就是在第i个房子（当前抢的金额是结果），选择就是抢或者不抢。

打家劫舍2对比1就是多了个环，结果我又死机了。原因是只执着于选择的改变，没有先把环带来的全局约束投影成有限种终局情况。
总结就是：如果两个不同的历史来到同一个状态，却拥有不同的未来合法选择，那么状态缺信息。

打家劫舍3对比前面就是把它变成了二叉树。思路其实想出来了：当前节点偷不偷？偷就是当前节点和孙子节点全部都能偷，不偷就是子节点都能偷。但是碍于不熟cpp（太久没写）没写出来TAT。

其实还有个4但和1-3都不大相同pass了（

题 本质 解法
打家劫舍 I 一维 DP：偷 / 不偷当前位置 正常备忘录dp
打家劫舍 II 环形 DP：拆成两个一维dp 分情况拆，让他退化成1
打家劫舍 III 树形 DP：节点偷 / 不偷 分层看：偷节点→孩子不能偷；不偷→孩子自由
