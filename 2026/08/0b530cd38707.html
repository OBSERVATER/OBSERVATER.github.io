链表双指针

发表于2026-08-26|更新于2026-09-03|面试
|总字数:2.1k|阅读时长:8分钟|浏览量:

出于找工作的目的刷无趣的算法题还是有些坐牢的，不过留个记录也好，以后还能靠ai帮我快速复习整理一下

种类

用在链表上的双指针有3种，分别是：

  • 快慢指针（不同起点）
  • 快慢指针（不同步长）
  • 两个链表上的两个指针

一般来说我喜欢在链表使用虚拟头节点，当需要创造一条新链表的时候，可以使用虚拟头结点简化边界情况的处理。

快慢指针（不同起点）

起点不一致的快慢指针：快指针先走 n 步，然后两个指针同时移动，快指针到达末尾时，慢指针正好在目标位置。

步骤

初始化：两个指针slow,fast都指向头节点。
快指针先行：快指针先移动 n 步。
同步移动：两个指针同时移动，直到快指针到达末尾（fast == nullptr）。
结果：慢指针正好指向倒数第 n 个节点。

使用场景

多半是那种定位倒数第n个节点这一类的

例子

leetcode No.19
描述：给定一个链表的头节点 head。
要求：删除链表的倒数第 n 个节点，并且返回链表的头节点。

输入：head = [1,2,3,4,5], n = 2
输出：[1,2,3,5]

输入：head = [1], n = 1
输出：[]

思路

快慢指针
删除倒数第n个节点就是删除正数第len-n+1个节点，即移动len-n次。
快指针先移动n次，然后慢指针和快指针同时移动，快指针移动了len次，慢指针就移动了len-n次。

快慢指针（不同步长）

同起点但移动的长度不同，比如快的走2步慢的走1步

步骤

初始化：两个指针都指向头节点。
不同步长：慢指针每次移动 1 步，快指针每次移动 2 步。
终止条件：快指针到达末尾或无法继续移动。

使用场景

找中点及其衍生（回文），或者找环，交点等

例子1

leetcode No.876

描述：给定一个单链表的头节点 head。
要求：返回链表的中间节点。如果有两个中间节点，则返回第二个中间节点。

输入：[1,2,3,4,5]
输出：此列表中的结点 3 (序列化形式：[3,4,5])
解释：返回的结点值为 3 。
注意，我们返回了一个 ListNode 类型的对象 ans，这样：
ans.val = 3, ans.next.val = 4, ans.next.next.val = 5, 以及 ans.next.next.next = NULL.

输入：[1,2,3,4,5,6]
输出：此列表中的结点 4 (序列化形式：[4,5,6])
解释：由于该列表有两个中间结点，值分别为 3 和 4，我们返回第二个结点。

思路

快的走2步，慢的走1步，快的走完了慢的才走了快的一半的路
抄模板就行

例子2

leetcode No.142

给定一个链表的头节点head，返回链表开始入环的第一个节点。 如果链表无环，则返回 null。

如果链表中有某个节点，可以通过连续跟踪next指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。如果 pos 是 -1，则在该链表中没有环。注意：pos 不作为参数进行传递，仅仅是为了标识链表的实际情况。

不允许修改链表。

输入：head = [3,2,0,-4], pos = 1
输出：返回索引为 1 的链表节点
解释：链表中有一个环，其尾部连接到第二个节点。

输入：head = [1,2], pos = 0
输出：返回索引为 0 的链表节点
解释：链表中有一个环，其尾部连接到第一个节点。

输入：head = [1], pos = -1
输出：返回 null
解释：链表中没有环。

思路

首先，快指针走2步，慢指针走1步，如果有环的话他们肯定会在某个节点相遇。如果说慢指针走了k步，快指针一定走了2k步。
既然走的路都是相同的，快指针和慢指针之间差了k步，这k步就是快指针在环内绕圈。

假设相遇点距环的起点的距离为 m，那么结合上图的 slow 指针，环的起点距头结点 head 的距离为 k - m，也就是说如果从 head 前进 k - m 步就能到达环起点。
巧了，从相遇点出发到达环起点的路程也是k-m。 如图:

也就是说，此时把随便一个指针丢回头节点，两个指针同步走k-m步后一定会相遇，相遇的地方就是环起点。

分离双指针

分离双指针：两个指针分别在不同的链表中移动，常用于合并、比较等操作。

步骤

初始化：两个指针分别指向两个链表的头节点。
条件移动：根据具体问题决定何时移动哪个指针。
终止条件：其中一个链表遍历完毕或满足特定条件。
应用场景：有序链表合并、链表比较等。

使用场景

合并两个有序链表
比较两个链表
找到两个链表的交点
其他需要同时处理两个链表的问题

例子

leetcode No.21

描述：给定两个升序链表的头节点 list1 和 list2。
要求：将其合并为一个升序链表。

输入：l1 = [1,2,4], l2 = [1,3,4]
输出：[1,1,2,3,4,4]

输入：l1 = [], l2 = []
输出：[]

输入：l1 = [], l2 = [0]
输出：[0]

思路

开一个虚拟头节点dummy代表合并后的链表
然后双指针开始运作，满足条件的放到dummy后面，然后向后走一步
直到双指针的其中一个跑完了，剩下的接到dummy->next

如果是合并k个链表(leetcode No.23)思路是一样的，无非就是怎么样更快的获取那个node。比如说是拿值最小的那个node。
此时使用priority_queue根据条件一个个先入队，出队的时候自然就是最小的那个了，其他思路都是一样的。
